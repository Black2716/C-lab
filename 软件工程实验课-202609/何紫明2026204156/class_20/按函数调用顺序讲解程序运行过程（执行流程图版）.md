# 按函数调用顺序讲解程序运行过程（执行流程图版）

这份文档的目标不是解释每一行代码的语法，而是按照“函数调用顺序”来理解程序如何运行。你可以把它想成程序的“执行路线图”。

我们以 [todo.c](./todo.c) 为主线，按真实执行路径来梳理。

---

## 1. 程序总体执行入口

程序的总入口是：

```c
int main(int argc, char *argv[])
```

也就是说，所有执行都从这里开始。

### 整体结构简图

```text
main()
  |
  ├─ get_data_path()
  |
  ├─ load_tasks()
  |
  ├─ 判断 argc
  |    |
  |    ├─ argc == 1
  |    |    └─ interactive_loop()
  |    |
  |    └─ argc > 1
  |         └─ handle_command()
  |
  └─ 返回退出状态
```

这表示：

- 程序启动后先确定数据文件位置
- 然后加载已有任务
- 接着判断用户是交互模式还是命令模式
- 最后执行对应逻辑

---

## 2. main() 的真实调用顺序

### 第一步：`main()` 启动时

```c
char *data_path = get_data_path();
TaskList list;
load_tasks(&list, data_path);
```

#### 调用顺序

```text
main()
  └─ get_data_path()
        └─ 返回 data_path

main()
  └─ load_tasks(&list, data_path)
        └─ 读取文件，恢复任务列表
```

#### 这一步意味着什么？

- 程序先知道数据文件放在哪里
- 然后从文件中加载上次保存的任务
- 在内存里重建 `TaskList`

这一步非常关键，因为它保证“程序退出后，任务还在”。

---

## 3. 程序进入两种模式

### 3.1 交互模式

```c
if (argc == 1) {
    interactive_loop(data_path);
    free(data_path);
    return 0;
}
```

当用户直接运行：

```bash
./todo
```

没有额外参数时，就进入交互模式。

### 调用链

```text
main()
  └─ interactive_loop(data_path)
        └─ while (1)
              ├─ fgets(input, ...)
              ├─ trim_newline()
              ├─ trim_spaces()
              ├─ tokenize_command()
              ├─ 处理命令
              └─ 继续循环
```

### 交互模式的关键顺序

```text
interactive_loop()
  └─ load_tasks(&list, path)

  └─ while (1)
        ├─ 读取用户输入
        ├─ trim_newline()
        ├─ trim_spaces()
        ├─ quit / exit 检测
        ├─ tokenize_command()
        ├─ 判断命令类型
        ├─ 执行对应功能
        └─ save_tasks()（部分命令执行后）
```

---

### 3.2 命令模式

```c
int handled = handle_command(&list, argc - 1, argv + 1, data_path);
```

当用户执行：

```bash
./todo add "学习C语言"
./todo list
./todo done 1
./todo delete 2
```

这种调用方式会直接把参数交给 `handle_command()`。

### 调用链

```text
main()
  └─ handle_command(&list, argc - 1, argv + 1, data_path)
        ├─ 判断命令名
        ├─ 执行 add/list/done/delete
        ├─ 可能调用 save_tasks()
        └─ 返回执行结果
```

这部分是程序最重要的“控制中心”。

---

## 4. 命令模式中的详细调用顺序

### 4.1 `handle_command()` 入口

```c
static int handle_command(TaskList *list, int argc, char *argv[], const char *path) {
```

它的第一个动作就是：

```c
if (argc == 0) {
    print_usage();
    return 0;
}
```

#### 执行路径

```text
handle_command()
  └─ argc == 0 ?
        ├─ yes: print_usage()
        └─ no : continue
```

如果用户没有传命令，就输出帮助信息。

---

### 4.2 判断命令种类

```c
const char *command = argv[0];
```

之后通过 `strcmp` 判断命令：

```c
if (strcmp(command, "help") == 0)
if (strcmp(command, "add") == 0)
if (strcmp(command, "list") == 0)
if (strcmp(command, "done") == 0)
if (strcmp(command, "delete") == 0)
```

#### 这部分可以画成这样的分支图

```text
handle_command()
  ├─ command == "help"
  |    └─ print_usage()
  |
  ├─ command == "add"
  |    ├─ 参数检查
  |    ├─ 组装 content
  |    ├─ add_task()
  |    ├─ save_tasks()
  |    └─ 输出成功信息
  |
  ├─ command == "list"
  |    └─ list_tasks()
  |
  ├─ command == "done"
  |    ├─ 参数检查
  |    ├─ atoi(argv[1])
  |    ├─ mark_done()
  |    ├─ save_tasks()
  |    └─ 返回
  |
  ├─ command == "delete"
  |    ├─ 参数检查
  |    ├─ atoi(argv[1])
  |    ├─ delete_task()
  |    ├─ save_tasks()
  |    └─ 返回
  |
  └─ 其他命令
       ├─ 报错
       └─ print_usage()
```

## 5. 添加任务：`add` 的函数调用顺序

假设用户执行：

```bash
./todo add "学习C语言"
```

### 调用顺序

```text
main()
  └─ handle_command()
        └─ command == "add"
              ├─ 检查 argc < 2 ?
              ├─ 组装 content
              ├─ add_task(list, content)
              |    └─ 新建 Task
              |          ├─ task.id = ...
              |          ├─ task.content = content
              |          ├─ task.done = 0
              |          └─ list->tasks[list->count++] = task
              |
              ├─ save_tasks(list, path)
              |    └─ 写入文件
              |
              └─ printf("任务已添加：...")
```

### 细化说明

#### `add_task()` 之前

```c
char content[MAX_CONTENT_LEN] = {0};
snprintf(content, sizeof(content), "%s", argv[1]);
```

这里将用户输入的字符串整理成任务内容。

#### `add_task()` 中

```c
Task task;
task.id = list->count == 0 ? 1 : list->tasks[list->count - 1].id + 1;
```

这一步是给任务分配编号。

然后：

```c
task.done = 0;
list->tasks[list->count++] = task;
```

把任务放入数组。

#### `save_tasks()` 中

```c
fprintf(fp, "%d|%s|%d\n", list->tasks[i].id, list->tasks[i].content, list->tasks[i].done);
```

把任务写入文件中，保证持久化。

## 6. 查看任务：`list` 的函数调用顺序

用户执行：

```bash
./todo list
```

### 调用顺序

```text
main()
  └─ handle_command()
        └─ command == "list"
              └─ list_tasks(list)
                    ├─ 判断 count == 0
                    ├─ 输出表头
                    ├─ 遍历数组
                    └─ printf 输出每个任务
```

### 关键过程

```c
for (int i = 0; i < list->count; i++) {
    printf("%2d  %s  %s\n",
           list->tasks[i].id,
           list->tasks[i].done ? "[√]" : "[ ]",
           list->tasks[i].content);
}
```

这里的逻辑很简单：

- 遍历任务数组
- 取出每个任务的编号、状态、内容
- 逐行输出

它不修改数据，只负责展示。

## 7. 完成任务：`done` 的函数调用顺序

用户执行：

```bash
./todo done 1
```

### 调用顺序

```text
main()
  └─ handle_command()
        └─ command == "done"
              ├─ int id = atoi(argv[1]);
              ├─ mark_done(list, id)
              |    ├─ 遍历数组
              |    ├─ 找到对应 id
              |    ├─ list->tasks[i].done = 1
              |    └─ 输出成功信息
              |
              ├─ save_tasks(list, path)
              |    └─ 写入文件
              |
              └─ 返回 0
```

### 关键点

#### `mark_done()` 的核心动作

```c
if (list->tasks[i].id == id) {
    list->tasks[i].done = 1;
    printf("任务 %d 已完成。\n", id);
    return 0;
}
```

这是典型的“按 ID 更新状态”的逻辑。

完成后必须写回文件，否则任务状态只存在内存中，程序重启后仍会丢失。

---

## 8. 删除任务：`delete` 的函数调用顺序

用户执行：

```bash
./todo delete 2
```

### 调用顺序

```text
main()
  └─ handle_command()
        └─ command == "delete"
              ├─ int id = atoi(argv[1]);
              ├─ delete_task(list, id)
              |    ├─ 先定位 index
              |    ├─ if 失败 -> 报错
              |    ├─ 后续元素整体前移
              |    ├─ list->count--
              |    ├─ 更新 id 重新编号
              |    └─ 输出成功信息
              |
              ├─ save_tasks(list, path)
              |    └─ 把新列表写回文件
              |
              └─ 返回 0
```

### `delete_task()` 的关键步骤

#### 1）查找目标位置

```c
for (int i = 0; i < list->count; i++) {
    if (list->tasks[i].id == id) {
        index = i;
        break;
    }
}
```

#### 2）整体前移

```c
for (int i = index; i < list->count - 1; i++) {
    list->tasks[i] = list->tasks[i + 1];
}
list->count--;
```

#### 3）重新编号

```c
for (int i = 0; i < list->count; i++) {
    list->tasks[i].id = i + 1;
}
```

这里体现的是极其典型的“删除后保持连续编号”的设计。

## 9. 交互模式的函数调用顺序

如果用户直接运行：

```bash
./todo
```

程序会进入交互模式：

```text
main()
  └─ interactive_loop(path)
        └─ load_tasks(&list, path)

        └─ while (1)
              ├─ printf("todo> ")
              ├─ fgets(input, ...) 读取一行
              ├─ trim_newline()
              ├─ trim_spaces()
              ├─ 判断空输入
              ├─ 判断 quit / exit
              ├─ tokenize_command(input, argv, ...)
              ├─ 根据 argv[0] 判断命令
              |    ├─ help
              |    ├─ list
              |    ├─ add
              |    ├─ done
              |    ├─ delete
              |    └─ unknown
              ├─ 处理逻辑
              └─ 继续下一轮循环
```

### 这个模式最关键的特点

它把程序变成了一个“持续运行的命令处理器”。

而不是只运行一次就退出。

这也是很多终端软件最典型的结构。

---

## 10. 终端输入如何被转成命令？

在交互模式中，用户输入：

```text
todo> add "学习C语言"
```

会先进入：

```c
tokenize_command(input, argv, 8, &argc);
```

然后调用：

```text
tokenize_command()
  ├─ 遍历字符
  ├─ 遇到空格切分参数
  ├─ 遇到双引号保持整体
  ├─ 生成 argv[]
  └─ 设置 argc
```

最后得到：

```text
argv[0] = "add"
argv[1] = "学习C语言"
argc = 2
```

于是程序就能像命令模式一样执行：

```c
if (strcmp(argv[0], "add") == 0) {
    ...
}
```

这说明：

- 交互模式和命令模式的核心处理逻辑是统一的
- 只是输入方式不同

## 11. 整体执行流程图（汇总版）

下面给你一个完整的调用图：

```text
main()
  |
  ├─ get_data_path()
  |    └─ 返回数据文件路径
  |
  ├─ load_tasks(&list, data_path)
  |    └─ 从文件中恢复任务
  |
  ├─ 判断 argc
  |    |
  |    ├─ argc == 1
  |    |    └─ interactive_loop(data_path)
  |    |          └─ while (1)
  |    |                ├─ 读取输入
  |    |                ├─ trim_newline
  |    |                ├─ trim_spaces
  |    |                ├─ tokenize_command
  |    |                ├─ 判断命令
  |    |                │    ├─ help
  |    |                │    ├─ list
  |    |                │    ├─ add
  |    |                │    ├─ done
  |    |                │    ├─ delete
  |    |                │    └─ unknown
  |    |                ├─ add_task / list_tasks / mark_done / delete_task
  |    |                ├─ save_tasks()（必要时）
  |    |                └─ continue / break
  |    |
  |    └─ argc > 1
  |         └─ handle_command(&list, argc - 1, argv + 1, data_path)
  |               ├─ 判断 command
  |               ├─ add_task / list_tasks / mark_done / delete_task
  |               ├─ save_tasks()
  |               └─ 返回状态码
  |
  └─ return 0 or 1
```

## 12. 用一句话理解整个执行过程

整个程序的主线可以概括为：

```text
启动 -> 读取文件 -> 分析命令 -> 执行操作 -> 更新内存 -> 写回文件 -> 退出
```

这就是一个非常典型的小型软件系统的生命周期。

---

## 13. 这份流程图的学习意义

你看完执行流程图后，应该能明白：

- `main()` 不是“所有代码都写在这里”，而是总入口
- 真正的业务逻辑由一系列小函数构成
- 数据保存和恢复是程序稳定性的关键
- 命令模式和交互模式本质上是同一套逻辑的不同入口
- 程序的行为是由“函数调用顺序”驱动的

这正是软件工程中最基础但最重要的一种理解方式：

“看程序，不只是看代码，而要看它的调用关系和执行链路。”

```text
main → get_data_path → load_tasks → 判断模式 → 进入交互/命令处理 → 执行 add/list/done/delete → save_tasks → 结束
```

这条调用链就是整个项目的核心骨架。
