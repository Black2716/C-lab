# 测试报告

## 1. 测试目标

验证命令行任务管理系统在以下场景下能够正常运行：

- 添加任务
- 查看任务
- 完成任务
- 删除任务
- 错误输入处理
- 数据持久化

## 2. 测试环境

- 操作系统：macOS / Linux
- 编译环境：gcc
- 语言：C
- 程序文件：`todo.c`

## 3. 测试用例

### 用例 1：添加单个任务

- 输入：`./todo add "学习C语言"`
- 预期：任务成功创建，输出提示信息。
- 结果：通过

### 用例 2：添加多个任务

- 输入：`./todo add "复习数据结构"`、`./todo add "完成软件工程作业"`
- 预期：两个任务都按编号顺序保存。
- 结果：通过

### 用例 3：查看任务列表

- 输入：`./todo list`
- 预期：输出所有任务编号、状态和内容。
- 结果：通过

### 用例 4：完成任务

- 输入：`./todo done 1`
- 预期：编号 1 的任务状态变为已完成。
- 结果：通过

### 用例 5：删除任务

- 输入：`./todo delete 2`
- 预期：编号 2 的任务被删除，后续编号重新整理。
- 结果：通过

### 用例 6：删除不存在的任务

- 输入：`./todo delete 999`
- 预期：输出错误提示，不影响其他任务。
- 结果：通过

### 用例 7：完成不存在的任务

- 输入：`./todo done 999`
- 预期：输出错误提示。
- 结果：通过

### 用例 8：空列表测试

- 输入：`./todo list`
- 预期：输出“暂无任务”。
- 结果：通过

### 用例 9：空内容添加

- 输入：`./todo add ""`
- 预期：拒绝添加并提示错误。
- 结果：通过

### 用例 10：交互模式

- 输入：`./todo`
- 预期：进入 `todo> ` 命令提示符，可执行 add/list/done/delete。
- 结果：通过

### 用例 11：退出程序

- 输入：`quit` 或 `exit`
- 预期：程序正常退出。
- 结果：通过

### 用例 12：持久化测试

- 步骤：添加任务之后退出程序，再重新启动。
- 预期：任务仍然存在。
- 结果：通过

## 4. 测试结论

经过上述测试，程序能够稳定处理基本功能需求，命令执行结果符合预期，能够实现任务的增删查改，并保留数据。

## 5. 发现与改进

- 程序支持最基础的数据保存与读取，后续可进一步扩展为支持多用户、分类、优先级等功能。
- 目前任务信息以文本文件保存，适合小规模任务管理场景。
